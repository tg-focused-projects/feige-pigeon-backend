> 文档状态：V1.0 产品基线  
> 确认日期：2026-08-27  
> 适用范围：产品、交互、视觉、前端、后端、测试与上线审核  
> 说明：本文优先级高于此前初版 PRD、后端初版契约及讨论草稿。具体价格、微信虚拟支付资格和最终视觉稿仍按本文标记继续确认。

## 1. 产品定义

《飞鸽传书》是一款：

> **真实地理距离 × 延迟通信 × 信鸽IP × 情绪社交 × 轻度收藏**

的微信小程序。

用户写下一封信，把它交给自己的鸽子。鸽子以统一的 **177 km/h**，根据发件城市与收件城市之间的距离计算旅程时间。

在鸽子抵达前，收件人不能查看正文。

产品不是一个“延迟发送消息”的工具，而是在制造一种可信的情绪体验：

> **真的有一只属于我的鸽子，跨越城市，把一封信送到另一个人手里。**

### 1.1 V1北极星

所有产品、视觉、文案和动效优先服务于：

- 鸽子具有生命感；
- 距离与等待真实发生；
- 送信和拆信具有仪式感；
- 用户愿意截图保存或分享旅程；
- 不能把鸽子替换成进度条后仍然完全成立。

### 1.2 核心用户关系

- 第一封信通过微信私下分享给认识的人。
- 分享时不提前绑定具体微信用户。
- 第一个完成城市确认并原子认领的用户，成为唯一收件人。
- 双方建立关系后，回信不再依赖微信分享。
- V1不提供陌生人匹配、附近的人、公开信件、广场、评论或群聊。

## 2. V1范围

### 2.1 V1必须包含

- 微信静默登录与用户身份建立；
- 自动获得一只免费鸽子“小白”；
- 写信、可选一张图片、可选称呼与落款；
- 出发城市定位或手动选择；
- 发送即起飞；
- 微信私人分享；
- 收件人城市确认与原子认领；
- 刚起飞、已在途中、早已抵达三种首次体验；
- 飞行 Hero 页面；
- 飞行进度本地重建；
- 极简旅途日志；
- 抵达、接信、拆信；
- 不显示已读回执；
- 直接回信；
- 信箱与往返信件；
- 首次发送后解锁完整鸽舍；
- 最多6只鸽子；
- 真实旅程数据展示；
- 5只额外付费鸽子的产品与数据模型；
- 到达及回信到达两类订阅通知；
- 起飞前内容安全审核；
- 最小内容投诉入口；
- 位置隐私与分享安全。

### 2.2 V1明确不做

- 等级、经验、升级；
- 速度成长；
- 体力、幸运、导航、防御等属性；
- 签到、喂食、虚拟币、抽奖；
- 广告解锁鸽子；
- 失联、死亡、搜救、复活；
- 真实天气影响抵达时间；
- 飞行事件互动和道具；
- 陌生人社交或共享天空；
- 用户公开主页；
- 公开城市足迹；
- 已读时间、催读和戳一戳；
- 复杂举报后台、自动处罚和用户拉黑；
- 语音、视频、多图和文件；
- 动态地图导航或精确位置追踪。

## 3. 用户身份与首次进入

### 3.1 静默登录

小程序启动后：

```text
wx.login
→ 后端 code2Session
→ 服务端建立可信登录态
→ 根据用户身份读取或初始化数据
```

用户不看到注册或登录页面。

V1不主动获取：

- 微信昵称；
- 微信头像；
- 手机号。

后端不能信任客户端裸传的 `openid`，应从可信服务端登录态解析当前用户。

### 3.2 自动获得小白

首次进入时自动创建免费鸽子：

```text
角色：小白
速度：177 km/h
状态：IDLE
累计里程：0
送达次数：0
```

不要求用户先起名。第一次成功送达后，再邀请用户改名：

> 它完成了第一次旅程。  
> 要给它起个名字吗？

可选择：

- 给它起个名字；
- 就叫小白。

### 3.3 第一次发送前的简化首页

首次发送前，不展示完整鸽舍、空位置或付费入口，也不展示完整 TabBar。

首屏建议：

```text
飞鸽传书

[正在休息的小白]

有些话，值得等它飞到。

把信交给小白。
它会按照你们之间的真实距离飞行，
抵达以前，对方看不到信里的内容。

[写第一封信]
```

可以提供低调入口：

- 我收到的信；
- 玩法说明；
- 设置与隐私。

### 3.4 完整结构解锁条件

第一次 `send` 真正成功后：

```text
has_sent_letter = true
```

解锁完整产品结构：

```text
鸽舍 ｜ 写信 ｜ 信箱
```

收信进入的新用户只有在自己完成第一次放飞后，才解锁完整鸽舍与付费入口。

## 4. 写信与放飞

### 4.1 写信内容

V1支持：

- 正文必填，最多500字；
- 普通文字与Emoji；
- 一张可选图片；
- 可选“写给谁”；
- 可选落款；
- 本地自动保存草稿。

不支持富文本与复杂排版。

“写给谁”、正文、图片和落款均属于私人信件内容，不能出现在公开分享参数中。

### 4.2 页面表达

写信页应像信纸，不像聊天输入框：

```text
写给：[一个你想起的人]

[信件正文]

添加一张照片（可选）

落款（可选）

[封好这封信]
```

### 4.3 封信

点击“封好这封信”后，信纸折入信封，进入轻量确认：

```text
给：小林
一封写好的信
附有一张照片
落款：凯杰

[重新打开修改]
[交给小白]
```

交给小白以前仍可修改；正式放飞以后不能修改正文。

### 4.4 出发邮戳与发件位置

位置获取不表达为“鸽子不知道自己在哪里”，统一采用“出发邮戳”隐喻。

文案：

> **这封信从哪里出发？**

> 为它盖上出发城市的邮戳，  
> 这段旅程才有起点。

隐私说明：

> 位置仅用于计算飞行距离和时间。  
> 收信的人不会看到你的精确位置。

操作：

- 主操作：使用我所在的城市；
- 备用操作：手动选择城市。

定位成功后播放短邮戳动画：

```text
广西 · 南宁
2026.08.27

南宁，已盖上出发邮戳
```

定位失败或拒绝时，允许手动选择城市，不要求具体地址。

### 4.5 内容安全审核

用户点击“放飞小白”后：

```text
文字安全检测
→ 图片安全检测
→ 检测通过
→ 创建正式信件
→ 记录 departure_time
→ 鸽子起飞
```

审核失败：

- 鸽子没有起飞；
- 不记录 `departure_time`；
- 不占用鸽子；
- 不生成分享链接；
- 保留草稿；
- 提示用户修改。

图片上传失败时允许重新上传或移除图片继续。

### 4.6 正式放飞

首次放飞前说明：

> 放飞后，小白会立即出发。  
> 对方需要等它抵达，才能拆开这封信。

点击“放飞小白”才调用正式发送接口。

发送成功意味着：

- 使用服务器时间记录起飞；
- 鸽子状态变为执行任务；
- 正文不可修改；
- 即使用户取消后续微信分享，起飞也不回滚。

### 4.7 起飞动画

约1.5至2秒：

```text
信封系到鸽子身上
→ 鸽子回头确认
→ 振翅离开
→ 天空展开
```

文案：

> **它出发了。**

> 从现在开始，时间已经在走。  
> 把它分享给你想寄信的人。

主操作：

> 让它去找那个人

## 5. 分享与未认领

### 5.1 分享内容

微信分享只携带不可猜测的 `shareToken`，不携带正文。

有落款时：

> 凯杰放飞了一只信鸽，它带着一封抵达后才能打开的信。

无落款时：

> 有个朋友放飞了一只信鸽，它带着一封抵达后才能打开的信。

分享图只展示：

- 鸽子；
- 信封；
- 产品名称；
- “抵达以前，不能拆开”。

不展示正文、用户图片、称呼、精确位置和信件ID。

### 5.2 取消分享

取消分享不是发送失败。

返回页面后：

> 小白已经出发了。  
> 它还没有遇见收信的人。

操作：

- 继续分享；
- 放飞30分钟后可召回。

首页同步进入已放飞、未认领状态。

### 5.3 未认领有效期

```text
unclaimed_expire_hours = 72
recall_grace_minutes = 30
```

规则：

- 30分钟内不突出召回，避免误触；
- 30分钟后发件人可以免费召回；
- 72小时仍无人认领，自动过期归巢；
- 召回或过期后旧分享永久失效；
- 重新放飞必须生成新分享凭证和新起飞时间；
- 不通过广告解除占用。

未认领期间不展示虚假距离、进度或ETA。

## 6. 收件预览与认领

### 6.1 分享打开后的安全预览

从微信分享进入时绕过首页，不展示完整 TabBar。

认领前可展示：

- 发件落款；
- 鸽子名字；
- 起飞时间；
- “抵达以前不能拆信”的规则。

不能展示：

- 正文与图片；
- 精确位置；
- 航程状态；
- 其他打开者；
- 收件人信息。

文案：

> **一只鸽子带着给你的信出发了。**

> 确认你所在的城市，  
> 看看它现在飞到哪里了。

主操作：

> 让它认出我

### 6.2 获取收件城市

用户主动点击后才请求位置。

自动识别到上海：

> **小白找到了上海**

> 要在这里收下这封信吗？  
> 确认后，这封信就只属于你。

操作：

- 在上海收下；
- 我在另一座城市。

自动定位失败时允许手动选择城市，并进入同一个确认流程。

### 6.3 原子认领

获得城市不等于认领成功。只有用户点击“在XX收下”，后端才执行原子认领。

规则：

- 第一个成功完成条件写入的人获得信件；
- 发件人不能认领自己的信；
- 同一收件人重复请求幂等返回；
- 不允许通过重复请求重新规划路线；
- 其他用户失败后只能看到“这只鸽子已经找到它要找的人了”；
- 不泄露获胜者身份和城市。

### 6.4 认领成功

成功后：

> **它认出你了。**

随后才计算并揭示航程状态。

## 7. 航程计算与首次体验

### 7.1 发送即起飞

发送时：

```text
status = FLYING_UNCLAIMED
departure_time = 服务器发送时间
recipient = NULL
distance = NULL
arrival_time = NULL
```

认领时：

```text
distance = sender_location → recipient_location
distance_duration = distance / 177 km/h
required_flight_time = max(distance_duration, 5分钟)
arrival_time = 原 departure_time + required_flight_time
```

禁止在认领时重置 `departure_time`。

### 7.2 最短旅程

```text
minimum_flight_time = 5分钟
```

用于同城、手动选择相同城市和极短距离场景。产品解释为起飞、辨认方向和落地本身也需要时间。

### 7.3 进度

```text
progress = clamp(
  (server_now - departure_time) /
  (arrival_time - departure_time),
  0,
  1
)
```

### 7.4 CASE A：才刚刚出发

条件：

```text
progress < 10%
```

约1.5至2秒回顾动画：

```text
发送城市
→ 信封系好
→ 鸽子起飞
→ 天空展开
→ 当前飞行位置
```

文案：

> **它才刚刚出发**

### 7.5 CASE B：已经在路上

条件：

```text
10% <= progress < 100%
```

镜头从出发城市沿路线推进，追上正在飞行的鸽子。

文案：

> **原来它已经在路上了**

> 在你打开这封分享以前，  
> 它已经飞了4小时26分。

### 7.6 CASE C：已经抵达

条件：

```text
progress >= 100%
```

播放精简旅程回顾，再根据“抵达后等待时间”进入接信或留信状态。

首次动画只自动播放一次；后续直接恢复对应页面。支持跳过与减少动态效果。

## 8. 飞行 Hero

### 8.1 视觉方向

V1采用：

> **天空横切面 / The Long Crossing**

核心构图：

```text
小白正在前往上海
逆风，但它没有停下来

南宁 ●──────🕊️────────○ 上海

预计还有
4小时39分

明天 06:42 抵达

已飞 786 km · 全程 1,607 km

[到了叫我]
```

### 8.2 信息优先级

1. 鸽子当前正在做什么；
2. 起点与终点城市；
3. 剩余时间；
4. ETA；
5. 已飞与总距离；
6. 最近旅途记录；
7. 到达通知。

剩余时间是唯一首要数字。

### 8.3 鸽子存在感

鸽子不是路线进度图标：

- 具有清晰角色轮廓和信封绑带；
- 有稳定飞行动作；
- 点击可显示一句当前状态；
- 不弹出复杂属性面板。

### 8.4 路线与隐私

- 使用抽象天空旅程，不做真实地图导航；
- 双方可见城市级起终点；
- 不显示精确坐标；
- 不暗示实时GPS追踪。

### 8.5 本地进度重建

接口返回：

```text
departureTime
arrivalTime
serverTime
```

前端建立服务器时间偏移并本地更新：

- 鸽子位置；
- 已飞距离；
- 剩余距离；
- 剩余时间。

只在首次进入、后台恢复、主动刷新和跨过抵达时间时同步后端，不每30秒轮询。

## 9. V1极简旅途日志

V1只保留4种随机事件：

- 遇到一点逆风；
- 穿过一层云；
- 看见远处灯火；
- 发现一些吃的。

数量：

```text
5分钟–2小时：0条
2–8小时：1条
8小时以上：最多2条
```

另固定记录起飞和抵达。

规则：

- 不影响速度和抵达时间；
- 同一封信确定性生成；
- 不重复插入；
- 只返回已经发生的事件；
- 六只鸽子使用相同事件类型、不同性格文案；
- V1不做天气系统、事件互动、延误、失联和道具。

## 10. 抵达、接信与拆信

### 10.1 抵达后的等待窗口

```text
pickup_wait_minutes = 30
pickup_deadline = arrival_time + 30分钟
```

抵达时：

- 结算真实旅程数据；
- 发送已授权的到达通知；
- 鸽子最多继续等待30分钟；
- 不依赖用户拆信完成统计。

### 10.2 用户正在页面等待

倒计时结束：

```text
鸽子沿路线抵达
→ 落地
→ 收起翅膀
→ 看向用户
```

文案：

> **它到了。**

主操作：

> 接过这封信

### 10.3 抵达30分钟内打开

- 0至10分钟：鸽子整理羽毛；
- 10至30分钟：鸽子坐着打盹。

文案：

> **小白刚到不久。**

或：

> **它还在这里等你。**

点击“接过这封信”后，鸽子立即归巢并恢复空闲。

### 10.4 超过30分钟打开

鸽子已经留下信件并归巢。

文案：

> **它已经来过了。**

> 小白等了你一会儿，  
> 把信妥善留在这里，然后回家了。

操作：

> 取出这封信

不再出现“叫醒小白”。

### 10.5 认领时已经抵达

如果认领时：

```text
now >= arrival_time + 30分钟
```

直接返回“已经留下信并归巢”。

如果：

```text
arrival_time <= now < arrival_time + 30分钟
```

进入“仍在等待接信”。

### 10.6 信封与拆信

接过或取出后进入统一信封页：

```text
广西 · 南宁 → 上海
飞行 1,607 km
历时 9小时05分

[拆开这封信]
```

约1秒拆信动画：

```text
信封翻转
→ 封口打开
→ 信纸拉出
→ 正文出现
```

正文页：

```text
写给：小林

[正文]
[可选图片]

—— 凯杰

小白为这封信飞行了1,607 km
从南宁到上海，用时9小时05分

[回一封信]
```

## 11. 送达回执与阅读隐私

发件人可以看到：

```text
等待认领
飞行中
已经抵达
已经被收下
```

发件人不能看到：

- 是否已读；
- 拆信时间；
- 阅读时长；
- 是否停留在正文页。

后端可保留 `read/read_at` 用于页面恢复和漏斗统计，但不能向发件人展示。

不提供催读、戳一戳和已读提醒。

## 12. 回信闭环

### 12.1 回信不依赖微信分享

原信件已经记录双方用户身份。

```text
新发件人 = 原 recipient
新收件人 = 原 sender
```

收件人身份必须由后端从原信件读取，不能由客户端重新指定。

### 12.2 回信流程

```text
拆信
→ 回一封信
→ 写信
→ 盖当前城市出发邮戳
→ 选择自己的空闲鸽子
→ 放飞
→ 直接进入IN_FLIGHT
→ 原发件人收到回信
```

回信：

- 不生成认领分享；
- 不经过 `FLYING_UNCLAIMED`；
- 不存在多人抢占；
- 默认飞往原发件信件的出发城市；
- 使用回信人的鸽子；
- 旅程数据归回信鸽子。

如果回信人的鸽子都忙，保存草稿，等有鸽子归巢后由用户主动放飞。

### 12.3 新关系与旧关系

```text
第一次联系：微信分享建立关系
后续往返：小程序内直接往返
写给新的人：创建新的未认领分享信
```

往返关系预留：

```text
thread_id
reply_to_letter_id
root_letter_id
```

## 13. 通知体系

V1只保留两类用户主动订阅。

### 13.1 当前鸽子抵达

飞行页操作：

> 到了叫我

发件人与收件人分别授权，分别收到对应通知。

### 13.2 回信抵达

原发件人可选择：

> 有回信时告诉我

回信真正抵达后再通知，不在回信刚起飞时推送。

### 13.3 不发送

- 分享打开；
- 认领成功；
- 飞行进度；
- 旅途日志；
- 即将抵达；
- 信件接过或拆开；
- 未认领即将过期；
- 里程变化；
- 付费营销。

后端订阅必须按信件、用户和类型独立记录，不能使用一个信件级 `subscribed/notified` 字段代表双方。

## 14. 鸽子与轻度养成

### 14.1 V1不做等级

V1不计算或展示：

- Level；
- EXP；
- 升级；
- 速度提升；
- 数值属性。

现有旧字段可以保留兼容，但业务逻辑不累加经验、不触发升级。

### 14.2 真实旅程数据

每只鸽子独立展示：

- 陪伴天数；
- 累计飞行里程；
- 成功送达次数；
- 最远旅程；
- 去过城市；
- 当前状态；
- 单次旅程履历。

每趟旅程保存原始事实，以支持未来重新设计称号、等级、城市邮戳和成就。

### 14.3 六只首发角色

| 角色 | 性格方向 |
| --- | --- |
| 小白 | 认真、有点谨慎 |
| 胖墩 | 贪吃、可靠 |
| 灰灰 | 安静、沉稳 |
| 阿闪 | 精神充沛、动作利落 |
| 老邮差 | 经验感、慢性子 |
| 花翎 | 好奇、爱看风景 |

名称与性格方向已确定为首发工作名，最终造型在 Character Sheet 阶段确认。

所有角色：

- 统一177km/h；
- 没有属性强弱；
- 具有不同外观、动作、性格文案和旅途表达；
- 每只一次只能执行一趟任务；
- 独立记录履历。

## 15. 多鸽与付费购买

### 15.1 数量

每个用户最多6只：

```text
第1只：免费小白
第2至第6只：付费获得
```

即最多同时执行6趟旅程，每只鸽子只能执行1趟。

### 15.2 购买价值

付费购买的是：

- 一个永久鸽舍位置；
- 一只永久角色鸽子；
- 一个独立送信名额；
- 该鸽子的独立履历和人格表现。

不出售速度、等级优势或抵达加速。

### 15.3 价格逻辑

价格绑定“第几个鸽舍位置”，不绑定具体角色。

```text
购买新位置
→ 从尚未拥有的角色中选择
→ 支付成功
→ 角色入住
```

第2至第6个位置价格逐步提高。具体人民币价格作为后台商品配置，待微信虚拟支付资格和费率确认后决定。

### 15.4 购买入口

只有完成第一次发送后，完整鸽舍和空位置才出现。

购买入口仅存在于：

- 鸽舍空位置；
- 鸽舍管理；
- 用户主动查看候选信使。

不在定位、收件、拆信、分享失败和鸽子忙碌时强制推销。

### 15.5 购买流程

```text
点击空位置
→ 查看候选鸽子
→ 选择角色
→ 确认扩建价格
→ 创建订单
→ 支付
→ 后端支付回调确认
→ 解锁位置并创建用户鸽子
→ 入住动画
```

同一用户不能重复拥有同一角色。

支付结果以后端回调为准，订单与权益发放必须幂等。

退款时不删除历史；若鸽子正在执行任务，当前旅程完成后再停止其发起新任务。具体退款规则以最终虚拟支付能力为准。

### 15.6 平台依赖

付费鸽子首发依赖新AppID实际获得虚拟支付资格。

产品与数据模型按支持付费设计，发布时使用能力开关：

```text
PAID_PIGEON_ENABLED
```

若资格尚未通过，不阻塞免费核心版本发布。

## 16. 完整信息架构

### 16.1 首次发送前

使用简化首页，不展示完整 TabBar。

### 16.2 首次发送后

底部导航：

```text
鸽舍 ｜ 写信 ｜ 信箱
```

- 鸽舍：默认首页；
- 写信：核心操作；
- 信箱：来信、寄出和往返记录。

设置、隐私、投诉和支付恢复放在低频入口，不单独设置“我的”Tab。

### 16.3 鸽舍首页

多只鸽子采用“一个主角 + 一排栖木”的结构，不做六张任务卡。

首页优先选中：

1. 刚完成旅程、等待反馈；
2. 正在飞行；
3. 未认领、需要继续分享；
4. 空闲小白；
5. 其他空闲鸽子。

顶部只显示简短汇总：

```text
2只正在路上 · 3只在家 · 1个空位置
```

空位置不抢主视觉，不持续显示价格。

### 16.4 写信入口

只有一只空闲鸽子时自动选择；多只空闲时，在封信和盖邮戳后选择“这次让谁出发”。

所有鸽子都忙时：

- 保存草稿；
- 查看正在飞行的鸽子；
- 不强弹购买页。

### 16.5 信箱

分为：

```text
来信 ｜ 寄出
```

来信优先级：

1. 已抵达、尚未接过；
2. 正在飞来；
3. 已拆开的历史信件。

寄出状态：

- 等待认领；
- 飞行中；
- 已经抵达；
- 已被收下；
- 已召回；
- 无人认领、已经归巢。

同一关系的往返信件采用叠放信封或旅程时间线，不使用聊天气泡。

### 16.6 深链路

- 微信分享：直接进入收件预览；
- 抵达通知：直接进入接信页；
- 回信通知：直接进入接信页；
- 不强制先经过鸽舍。

## 17. 内容、投诉与隐私

### 17.1 最小投诉功能

V1保留“内容投诉与反馈”，不做删除和拉黑。

类型：

- 不当内容；
- 骚扰或诈骗；
- 侵犯隐私；
- 其他。

记录：

```text
letter_id
reporter_user_id
reported_sender_user_id
reason
description
status
created_at
```

由运营先人工处理，不做自动封禁和复杂申诉系统。

### 17.2 位置最小化

定位仅用于计算距离和城市级旅程。

长期保存：

- 省份；
- 城市；
- 城市编码；
- 模糊坐标或城市中心点；
- 最终距离。

不在前端、分享参数、日志和无权限接口中返回精确经纬度。

### 17.3 城市足迹

用户可以在自己的鸽子履历中查看城市邮戳，但：

- 不公开完整足迹；
- 不向其他用户展示常去城市；
- 默认分享截图不包含完整城市历史。

### 17.4 信件保存

- 已送达信件默认保存在私人信箱；
- V1不提供发件人远程撤回已认领信件；
- 召回只适用于未认领信件；
- 数据删除与账号注销以后续正式隐私政策为准。

## 21. 视觉与交互阶段约束

下一阶段优先级：

```text
Visual Bible最终版

```

视觉必须遵循：

- 复古邮政 × 手绘鸽子 × 信纸质感 × 现代极简；
- 成年人愿意使用，不过度儿童化；
- 不使用AI紫蓝渐变、SaaS Dashboard、满屏玻璃卡片、霓虹和无意义大圆角；

- UI以普通小程序组件为主，Canvas/SVG只用于真正动态的路线和局部效果；
- 动效服务于生命感、等待感和仪式感。

在飞行Hero方向与小白角色确认以前，不大规模铺开全部页面。
