## 二、部分实现 ⚠️（有差异，需确认）

| 规格条目 | 规格要求 | 现状差异 | 建议 |
|---|---|---|---|
| 12.2 回信直接 IN_FLIGHT | 回信不经过 FLYING_UNCLAIMED，直接 IN_FLIGHT | 回信实际 status=FLYING_UNCLAIMED（因收件人已预绑定，无人能抢，行为等价"直达"） | 语义对齐：回信创建时直接置 IN_FLIGHT（小改），或前端按"已预绑定"处理 |
| 13.1/13.2 通知体系 | 发件人+收件人**分别**订阅；回信到达通知 | 当前仅收件人订阅到达（信件级 `subscribed` 单字段），**发件人订阅未实现**，回信到达通知未实现 | 列入 V1.1（需加订阅表/双方字段） |
| 8.2 飞行 Hero 剩余时间 | 剩余时间是唯一首要数字 | flight 返回 progress/剩余时间可计算 ✅，但无"剩余时间"聚合字段 | 前端自行计算，或后端补 remainingMs 字段（可选） |
| 3.1 静默登录 | 后端不能信任裸传 openid，应从服务端登录态解析 | 当前业务接口**直接传 openid 参数 + sign 校验**（sign=md5(openid+secret)，secret 仅后端持有，等效防伪） | 架构上可接受（sign 已保证 openid 不可伪造），如需严格服务端会话再升级 |
| 15 多鸽/购买 | 最多6只、付费购买 | **完全未实现**（见下"未实现"） | 依赖微信虚拟支付资格 |
| 14.1 等级经验 | **V1 明确不做**等级/经验/升级 | ✅ **已按决策关闭结算**（commit 487110d）：仅累积里程/送达次数，exp/level/speed 不再变更 | 已处理 |
